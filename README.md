# 受取帳（Receipt Ledger）

レシートメール・決済通知メールから支出を集計するツール。

**メールの内容は一切外部に送信されません。** 解析はすべてブラウザの中だけで完結します。

## 使い方

1. [受取帳を開く](https://poko8725.github.io/receipt-ledger/)
2. デスクトップなどに空のフォルダを作る
3. Mail.app で対象のメールを選び（`⌘A` で全選択）、**そのフォルダへドラッグする**
   - 1通につき1つ `.eml` ができます
4. できた `.eml` をまとめてドロップする
5. マーチャント別の集計が出る。CSV で書き出せる

インストール不要、アカウント登録不要です。
どう動くか先に見たい場合は、ページ内の「サンプルデータで試す」から確認できます。

> **メールソフトからブラウザへ直接ドラッグしても読み込めません。**
> Mail.app はファイルそのものではなくファイルプロミス（「要求されたら書き出す」という約束）を
> 渡すため、ブラウザ側がファイルとして受け取れません。Finder のフォルダは
> このプロミスを解決できるので、いったん経由する必要があります。
>
> なお macOS 26 の Mail.app には `ファイル → 書き出す…` がありません。
> `.eml` を作る手段は Finder へのドラッグか、1通ずつの `別名で保存…` になります。
> この手間を丸ごと無くしたい場合は下の CLI 版を使ってください。

## 出力

- **CSV** — サマリー（請求元別）と明細の2種類
- **PDF** — 「PDFで保存」からブラウザの印刷機能で保存します
  （PDF 生成ライブラリは使っていません。日本語 PDF はフォント埋め込みで数MBになり、
  「HTML 1枚・依存ゼロ」と両立しないためです）

## 外貨

`$12.34` のようなドル建て、EUR・GBP にも対応しています。

**通貨をまたいで合計することはありません。** 円とドルを足した数字は出しても意味がないため、
集計キーに通貨を含めて構造的に混ざらないようにしています。

円換算したい場合は2通りあります。

- **最新レートを取得** — ボタンを押したときだけ [frankfurter.dev](https://frankfurter.dev/)
  （欧州中央銀行のデータ）へ問い合わせます
- **手入力** — レートを直接入れれば、通信せずに計算できます

## 「メールを送信していない」ことの確かめ方

口約束ではなく、次の3つで確認できます。

- **外部リソースを読み込んでいない** — フォントも含めて外部ファイルは1つも参照していません。
  HTML 1枚に全部入っています。
- **Content-Security-Policy で禁止している** — ページ自体が `default-src 'none'` を宣言し、
  `connect-src` は為替レート配信元1ホストだけに限定しています。
  それ以外へはコードが何をしようとブラウザが通信を拒否します。
- **オフラインで動く** — Wi-Fi を切っても解析・CSV・PDF はすべて動きます
  （レート取得だけが失敗します）。動くなら、送信していません。

DevTools の Network タブを開いたまま使ってもらうのが一番早い確認方法です。
レートを取得しない限り、リクエストは1件も出ません。

## 対応しているマーチャント

Amazon / 楽天市場 / Apple / セブン-イレブン / ファミリーマート / ローソン /
Uber Eats / Netflix / Spotify

判定できなかったものは「不明」にまとまります。金額が取れなかったメールはスキップされます。

ルールは `index.html` 内の `MERCHANT_RULES` と `AMOUNT_PATTERNS` に書いてあります。
対応してほしいマーチャントがあれば Issue で教えてください。

## CLI 版（書き出し不要）

`cli/` に Python 版があります。標準ライブラリのみで動きます（追加インストール不要）。

**Mail.app のデータを直接読むので、`.eml` の書き出し作業が要りません。**

```bash
cd cli && python3 -m receipt_ledger --source apple-mail --since 2026-01-01 --output summary.csv
```

初回はフルディスクアクセスが必要です。許可していない場合は手順を表示して終了します。
権限を与える対象は Python ではなく、**コマンドを実行しているアプリ**（Terminal.app、iTerm など）です。

**次のメールボックスは既定で読みません。** 全部読ませたいときは `--all-mailboxes`。

- **ゴミ箱・迷惑メール** — 捨てたメールを拾い直すと、当選通知や広告が集計に戻ってきます。
  実データでは、ゴミ箱を含めた場合の余剰の7割がこれでした
- **下書き・送信済み・Outbox** — 自分が書いたメールは領収書ではありません。
  下書きは Mail.app が自動保存の版を別ファイルで持ち、まだ Message-ID が付いていないので
  重複判定も素通りします。実データでは、書きかけの1通が5桁の取引4件になっていました

メールボックスを絞ることもできます。

```bash
cd cli && python3 -m receipt_ledger --list-mailboxes
cd cli && python3 -m receipt_ledger --mailbox "すべてのメール" --since 2026-01-01
```

`--list-mailboxes` は**通数も出します**。Gmail のラベルは Mail.app 上では独立した
メールボックスに見えますが、実体は「すべてのメール」にあり、ラベル側は空の器に
なっていることがあります。名前は合っているのに 0 件、という一番読みにくい形に
なるため、指定が空振りする場合は走査前に止めて理由を出します。

書き出し済みフォルダを読ませることもできます（フルディスクアクセス不要）。

```bash
cd cli && python3 -m receipt_ledger --source eml-dir --input-dir ./exported_mails
```

IMAP で取りに行くこともできます（OS を問わず、書き出し作業も不要）。

```bash
export IMAP_USER='自分のアドレス'
export IMAP_PASS='アプリパスワード'
cd cli && python3 -m receipt_ledger --source imap --since 2026-01-01
```

**資格情報は保存しません。** 環境変数からしか読まず、設定ファイルにも OS の
資格情報ストアにも書きません。アプリパスワードは2段階認証を有効にしてから
発行してください（`IMAP_HOST` の既定は `imap.gmail.com`）。
取りに行く先は元々自分のメールが置いてあるサーバなので、第三者へは何も送っていません。

フォルダ名は `--list-folders` の出力をそのまま `--imap-folder` に渡すのが確実です。
日本語のフォルダ名は修正 UTF-7 で表されるため、見た目と一致しません。

IMAP が閉じている Exchange Online 環境には対応していません（OAuth とアプリ登録、
管理者同意まで必要になるため）。その場合は `.eml` を書き出して `--source eml-dir` を使ってください。

主なオプション:

| オプション | 内容 |
|---|---|
| `--source` | `apple-mail`（既定） / `eml-dir` / `imap` |
| `--since` / `--until` | `YYYY-MM-DD` で期間を絞る（手元のタイムゾーンの日付で判定します） |
| `--output` | 集計 CSV の出力先（既定 `summary.csv`） |
| `--detail-output` | 明細 CSV も出す |
| `--imap-folder` | IMAP のフォルダ名（既定 `INBOX`） |
| `--list-folders` | IMAP のフォルダ一覧を出して終わる |
| `--mailbox` | Mail.app のこのメールボックスだけ読む（複数回指定可・名指しは既定の除外より強い） |
| `--list-mailboxes` | Mail.app のメールボックス一覧を通数つきで出して終わる |
| `--all-mailboxes` | 既定で除外しているメールボックス（ゴミ箱・迷惑メール・下書き・送信済み）も読む |
| `--keep-duplicates` | 同じ取引が複数の通知で届いたぶんも、そのまま数える |
| `--duplicate-window` | 同じ取引とみなす日数の幅（既定 3） |

日付は**受け取った人のタイムゾーン**に直してから扱います。領収書は
`-0700` のように送信側のタイムゾーンで届くので、書かれたままの日付で
期間を判定すると、手元の暦では範囲に入っているメールが静かに落ちます。
明細 CSV の「日付」列も同じ基準です。

### 取得元を増やす

`cli/receipt_ledger/sources/` に1ファイル足して `sources/__init__.py` に登録するだけです。
解析・集計側は変更不要になっています。

ソースの責務は「RFC 822 のバイト列を1通ずつ返す」ことだけで、Mail.app も Gmail
（`messages.get(format="raw")`）も IMAP（`FETCH RFC822`）も同じ形に落ちるためです。
詳細は `sources/base.py` に書いてあります。

## 制約

- 金額抽出は正規表現ベースなので、フォーマットによっては取り違え・取りこぼしがあります。
  **金額は必ず元のメールで確認してください。** 会計処理にそのまま使える精度は保証していません。
- **「そのメールが取引かどうか」は判定していません。** 金額の形をした数字の周りを見て、
  賞品の価値・送料無料のしきい値・値上げの予告・ゲーム内通貨の個数は弾きますが、
  判定しているのは数字の文脈だけです。値上げの本文に月額が書いてあれば支払いとして読みます。
- **同じ取引の寄せ方は確実ではありません。** 同じ相手・同じ金額が数日以内に並び、
  件名から段階（注文／発送など）が読めるときだけ寄せます。同じ日に別の商品を同じ額で
  2回注文すると、寄せてしまいます。**寄せたぶんは必ず画面に出す**ので、
  違っていれば `--keep-duplicates` で外してください。
  なお**通貨が違うと寄せられません。**決済代行が円で、販売元がドルで領収書を出すと、
  同じ取引が JPY と USD に1件ずつ立ちます。為替を持っていないので突き合わせられません。
- **1通に複数の明細が入っていても、1件としてしか数えません。**
  ストアの領収書は複数のアプリ購入をまとめて1通で送ってくることがあります。
  その場合、金額は「合計」を取るので**総額は合いますが、内訳は分かれません**。
  請求元も1件に潰れるため、**合計の全額が1つのアプリに付きます。**
  勘定科目や家事按分を明細単位でやりたい場合は、元のメールを見てください。
  （2026-08-05 まではここで**合計ではなく明細の1件目**を拾っていました。
  手元の実データでは Apple の領収書 401 通のうち 14 通、計 ¥27,660 が欠けていました。
  総額の取り違えは直しましたが、内訳が分かれない点は未対応です。）
- `.eml` の書き出しは手動です。メールソフトとの直接連携はしていません。
